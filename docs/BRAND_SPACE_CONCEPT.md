# 포온 브랜드 가이드: 먼저 떠나는 여행

사이트, 앱, 이미지, 문구가 모두 이 문서를 기준으로 맞춥니다. 디자인이 바뀌어도 세계관과 문구 규칙은 유지합니다.

## 1. 한 줄 정의

**포온은 반려동물의 여행을 함께 준비하고 배웅하는 동네 안내소입니다.**

반려동물과의 삶 전체를 하나의 여행으로 봅니다. 이별을 갑작스러운 단절이 아니라, 함께 준비해 온 여행의 한 장면으로 만들어 보호자가 덜 아프게 합니다(펫로스 예방). 무겁지 않게, 하지만 가볍게 다루지도 않습니다.

## 2. 세계관

| 시기 | 여행으로 보면 | 포온에서 | 분위기 |
|---|---|---|---|
| 함께 사는 동안 | 여행 준비, 여권 만들기 | 펫패스(여권), 미용·호텔·펫택시 이용 기록, 멍BTI | 밝고 경쾌함, 3D 캐릭터 사용 |
| 떠나는 날 | 출발, 배웅 | 장례: 가장 가까운 곳에서 차분하게 배웅 | 고요하고 따뜻함, 캐릭터 없음 |
| 떠난 뒤 | 별에 도착, 편지 | 추억상자(별자리), 부고장(출발 소식), 49일·1주기 편지 | 그리움, 희망 |

포온 자체는 "우리 동네 정거장"입니다. 어디로 가든 가장 가까운 곳에서 출발할 수 있게 길을 찾아 주는 곳입니다.

## 3. 말투

- 다정하지만 담백하게 씁니다. 감정을 과장하지 않습니다.
- 이별을 숨기지 않습니다. "죽음"이라는 말을 피하려고 어색하게 돌려 말하지 않되, 화면 문구에서는 "떠나다", "배웅", "먼저 떠난 아이"를 씁니다.
- 슬픔을 없애 준다고 약속하지 않습니다. 함께 준비하고 곁에 있겠다고 말합니다.
- 사실(비용, 허가, 법)은 은유 없이 정확하게 씁니다.

### 용어

| 쓰는 말 | 피하는 말 | 비고 |
|---|---|---|
| 배웅, 떠나는 날, 먼저 떠난 아이 | 처리, 폐기 | 법 안내에서는 "사체"를 정확한 용어로 사용 |
| 우리 동네, 가까운 곳 | 최고의, 프리미엄, 완벽한 | 확인되지 않은 최상급 표현 금지 |
| 별이 된 아이 | (장례 페이지의 귀여운 표현, 로켓 이모지) | 앱·추억상자 안에서만 |
| 허가 업체, 등록 업체 | 공식 파트너, 인증 업체 | 법적 용어 그대로 |
| 아이가 먼저 떠났어요 | 무지개다리를 건넜어요, 사망 처리 | 아이 상태를 바꾸는 설정 문구(9장) |

### 검색어는 제목에 그대로

- 페이지 제목(H1·title)에는 사람들이 실제로 검색하는 말을 씁니다: "광진구 반려동물 장례식장", "강아지 장례 비용", "애견미용".
- 여행·우주 은유는 부제, 일부 소제목, 이미지, 앱에서만 씁니다.
  - 예: 제목 "광진구 반려동물 장례식장" / 부제 "아이가 먼저 떠나는 여행, 가장 가까운 곳에서 배웅할 수 있도록"

## 4. 문구 규칙 (AI 티 방지)

- **긴 줄표(—, –) 금지.** 마침표, 쉼표, 괄호로 바꿉니다. 범위는 하이픈(20만 ~ 30만 원은 물결표 그대로).
- 히어로: 제목 2줄 이하, 부제 20단어(한국어 약 40자) 이하, 텍스트 요소 4개 이하. 지표·칩은 히어로 밖으로.
- 섹션 위 작은 라벨(eyebrow)은 세 섹션에 하나까지만 씁니다.
- 한 의도에 한 라벨만 씁니다.

| 의도 | 라벨 |
|---|---|
| 전화 걸기 | 전화 상담 |
| 상담 폼 | 상담 남기기 |
| 지역 찾기 | 우리 동네 찾기 |
| 장례로 가는 입구 | 장례 안내 |
| 장례식장 목록 | 장례식장 찾기 |
| 상담 서비스를 아직 못 정함 | 아직 모르겠어요 |
| 앱으로 이동 | 포온 앱 |

- 지어낸 숫자, 후기, 업체를 쓰지 않습니다. 모든 수치는 출처가 있어야 합니다.
- "혁신적인", "새로운 차원의", "완벽한" 같은 빈말은 쓰지 않습니다.

## 5. 디자인 시스템

### 화면 구성
- 모든 페이지는 **히어로(밤) → 본문(달빛 밝은 면)** 으로 한 번만 전환합니다. 본문 중간에 다시 밤으로 돌아가지 않습니다(가이드 옆 상담 카드처럼 작은 카드 한 장은 예외).
- 모바일 하단은 사이트·앱 공통 하단 탭(홈·장례·미용·추억상자·내 정보)입니다. 사이트 화면에서는 탭 위에 "전화 상담"·"상담 남기기" 알약이 함께 뜹니다(`<BottomNav call />`). 탭 구성을 바꾸는 시점은 9장의 결정 대기입니다.
- 화면마다 시간대(함께 사는 날의 낮, 배웅하는 날의 밤)를 나눕니다. 규칙은 9장입니다. 지금은 모든 사이트 페이지가 밤 머리로 시작하고, 낮 화면의 밝은 머리는 다음 단계에서 바꿉니다.

- 장례·가이드 페이지에는 라임을 쓰지 않습니다. 강조는 흰색(밤 위)이나 ink(밝은 면)로 합니다.
- 보라·네온 글로우는 쓰지 않습니다. 새벽 복숭아빛은 일러스트 안에서만 씁니다.

### 모양
- 카드 20px, 큰 타일 28px, 버튼은 둥근 알약형(pill), 입력창 12px.
- 정보 카드는 **탑승권**처럼 만듭니다: 흰 카드, 한쪽에 점선 절취선과 반원 홈.
- 아이콘은 lucide(프로젝트가 이미 사용 중), 선 굵기 1.75로 통일합니다. 서비스 대표 그림은 생성한 3D 행성 아이콘을 씁니다.

### 글꼴
- Pretendard 하나만 씁니다. 강조는 굵기로만 하고, 다른 글꼴을 섞지 않습니다.

### 움직임 (MOTION 4)
- 히어로 별이 아주 천천히 반짝임(CSS), 카드에 마우스를 올리면 살짝 떠오름, 섹션이 처음 보일 때 한 번 올라오며 나타남.
- `prefers-reduced-motion`이면 모두 끕니다.

## 8. 앱 화면 (사이트와 한 브랜드로)

2026-11-07부터 앱((app) 라우트 그룹)도 사이트와 같은 색, 글꼴, 카드, 화면 구성을 씁니다. 예전의 회색 검정 화면(#0A0A0B, #121212, #1C1C1E 등)과 주황(#FF5500), 이모지 아이콘은 쓰지 않습니다. 기준 화면은 하단 탭(`src/components/shared/BottomNav.tsx`)과 내 정보(`/mypage`)입니다. 앱 홈은 사이트 홈(`/`)으로 합쳤습니다(9장).

### 구성
- 앱 전체는 `.app` 범위 안에 있습니다(`src/app/(app)/layout.tsx`). 바탕은 달빛(moon)입니다. 데스크톱에서는 위에 사이트 머리 메뉴가 붙고, 그 아래 밤하늘 위에 휴대폰 폭 화면이 떠 있습니다(좌우 배너는 없앴습니다). 글꼴은 Pretendard(루트 레이아웃에서 불러옴)입니다.
- 화면마다 **위쪽 밤 → 아래 달빛 본문**으로 한 번만 바뀝니다.
  - 탭 첫 화면(홈, 내 상담, 추억상자, 내 정보)과 큰 소개 화면: `<AppHero>` (밤, 별, 아래 모서리 28px 둥글게, 큰 제목 + 부제).
  - 하위 화면, 입력 흐름, 상세 화면: `<AppTopBar>` (밤색 윗줄, 뒤로 가기 + 제목, 화면 위에 붙음). 입력 흐름의 진행 표시는 `<AppProgress>`.
  - 화면 전체가 밤인 화면은 만들지 않습니다. 예외: 사진 크게 보기(라이트박스), 3D 등록 완료 연출 같은 짧은 전체 화면 연출.
- 하단 탭은 사이트 모바일 하단 바와 같은 밤색 플로팅 알약입니다. 입력 흐름 화면의 주 버튼은 `<AppBottomAction>` 안에 둡니다.

### 규칙
- hex 색(`bg-[#...]`), `text-white`, `text-black`, `text-gray-*`, `bg-gray-*`, 보라·파랑·분홍 Tailwind 색을 쓰지 않습니다. 밤 위의 반투명 겹(`bg-white/10`, `ring-white/20`)만 예외입니다.
- 라임은 버튼 배경과 활성 표시(하단 탭, 진행 표시, 작은 추가 배지)에만, 화면당 강조 버튼 하나까지 씁니다. **추억상자·부고장·편지·장례 관련 화면에는 라임을 쓰지 않습니다.**
- 이모지를 화면에 쓰지 않습니다. lucide 아이콘(선 굵기 `APP_ICON_STROKE` 1.75) 또는 3D 클레이 아이콘으로 바꿉니다. 사진이 없는 아이 자리는 `PawPrint` 아이콘입니다.
- 모양: 카드 20px, 큰 타일·시트 28px, 입력 12px, 버튼은 알약. 그림자는 남색 기운(`rgb(31 39 66 / …)`)으로만.
- 글자 크기: 제목 26px(AppHero), 소제목 18px, 본문 15~16px, 캡션 13px 이상. 입력창 글자는 16px(iOS 확대 방지).
- 문구는 4장 규칙(긴 줄표 금지, 한 의도 한 라벨)을 따릅니다. 기능 문구를 새로 지어내지 않습니다.
- 움직임은 누를 때 1px 내려가는 정도와 시트 열림 정도만. `motion-reduce` 를 지킵니다.

## 9. 낮과 밤 (일상 서비스와 장례 나누기)

2026-11-09 제안 "포온 두 시간대 설계안"의 1단계입니다. 미용을 보러 온 보호자가 이별을 먼저 만나지 않게 하고, 아이를 막 떠나보낸 보호자가 밝은 홍보를 만나지 않게 합니다. 이별을 숨기지는 않습니다.

### 시간대

### 지금 지키는 것 (1단계)
- **장례를 기본값으로 두지 않습니다.** 서비스가 정해지지 않은 화면(홈 동네 고르기, 동네 안내, 상담 폼 선택지)은 일상 서비스 먼저, 장례는 맨 뒤입니다(`liveServicesEverydayFirst`).
  - 홈 동네 고르기의 기본값은 '전체 서비스'라 동네 안내(`/area/…`)로 갑니다.
  - 상담 폼은 서비스를 꼭 받습니다. 모르면 '아직 모르겠어요'(`LEAD_SERVICE_UNSURE`, `src/lib/site/lead-options.ts`)입니다.
- **하단 '상담 남기기'는 보던 서비스를 들고 갑니다**(`/contact?service=grooming`). 서비스를 알 수 없는 화면은 `/contact` 로 가고, 폼에서 '아직 모르겠어요'로 시작합니다.
- **장례 입구는 늘 같은 자리에 같은 이름으로 둡니다.**
  - 홈 첫 화면 버튼 아래 한 줄 "아이가 먼저 떠났다면 · 장례 안내"(달 아이콘, 색 없음, 누르는 높이 44px 이상)입니다.
  - 장례 탭을 빼기 전에 이 입구를 먼저 둡니다.
- **가이드 목록은 '함께 사는 날 → 배웅하는 날과 그 뒤' 순서입니다.** 대표 글은 미용 글 하나(그림)와 장례 글 하나(글자 한 줄)입니다.
- **부고장 공개 링크는 차분하게 둡니다.** 전용 미리보기(라임·앱 소개 없음)를 쓰고 하단 탭을 띄우지 않습니다.
- **'이벤트' 같은 판촉 말은 장례 화면에 쓰지 않습니다.** 업체 가격표의 '이벤트가'는 뜻을 바꾸지 않고 '할인가'로 적습니다.
- **홈 화면에 추가할 수 있습니다**(`src/app/manifest.ts`, 아이콘 `public/icons/icon-*.png`, `src/app/apple-icon.png`). 설치를 권하는 팝업은 띄우지 않습니다.
  - 아이콘은 지금 브라우저로 열립니다(display "browser").
  - 독립 창(standalone)은 DB 복구 뒤 실제 아이폰에서 카카오·구글 로그인이 끝나는 것을 확인한 다음 켭니다. 독립 창은 Safari 와 쿠키를 나눠 쓰지 않아 로그인이 끊길 수 있기 때문입니다.
- **하단 '상담 남기기'는 가이드 글에서도 그 글의 서비스를 넘깁니다.** 사이트 레이아웃이 글 주소 → 서비스 표를 만들어 넘깁니다.
- **상담 폼은 실패해도 적은 내용과 고른 서비스를 지우지 않습니다.** React 19 의 폼 자동 초기화를 쓰지 않고 직접 보냅니다.

### 결정 대기 (대표님)
- 하단 탭을 [홈 · 서비스 · 우리 아이 · 내 정보] 4개로 바꾸는 시점. 제안은 DB 복구 뒤, 홈에서 장례로 가는 흐름을 확인한 다음입니다.
